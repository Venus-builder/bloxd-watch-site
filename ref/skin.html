スキンビューア(プレイヤーの見た目の確認ツール)

手元で作った見た目の確認ツールの機能と、見た目の仕組み。ツール本体は、公式の素材を含むので、公開していません。

このページは、手元で作った「Bloxd スキンビューア」の機能と、そこから分かった見た目(スキン・コスメ)の仕組みをまとめたものです。ビューア本体は、公式のプレイヤーモデルと公式テクスチャを中に埋め込んでいるので、このサイトには置いていません(公式の素材を公開で再配布しないため)。下の「分かったこと」は、ビューアの調査メモの内容で、私は元のビルドで、もう一度は確かめていません(確かさの印に ビューアの調査メモより と書きます)。確認したビルド: x17cru(今のビルドの確認日ではありません)。

1. ビューアで、できること

タブできること
持ち物右手・左手を切り替えて、アイテムを持たせる。回転・位置・大きさをスライダーで調整できる(左手は鏡像の置き方。値は手ごとに保存)。
ポーズ9 種類の見本(立つ、手を振る、ビクトリー、指差し、考え中、敬礼、すくめる、リラックス、狙う)と、頭・両腕・両脚・胴の全関節を、スライダーで自由に回転(X=前後、Y=ひねり、Z=左右、単位は度)。ドラッグで視点を回し、ホイールで拡大・縮小。
見た目ゲーム内の「Characters → Default」の 8 人のスキンを選ぶ。防具(素材とスロットを選ぶ、フル装備、すべて外す)。コスメ名の文字列(JSON か、skin_0_5 のような名前)を貼って「反映」。
モブ公式モデルに入っているモブを表示して、足と腕を振る簡単な歩行を見られる(表示中は、プレイヤー用のタブは、一時的に使えない)。
出力透過 PNG で保存。現在の見た目の各部品のセルを、1 枚に並べた「64×64 風スキン画像」も保存できる。

2. 分かったこと(見た目の仕組み) ビューアの調査メモより

項目内容
プレイヤーのモデルファイル名は Player_Model.glb。32 個のメッシュで、Draco 圧縮。頭は 9×9×9 テクセル、腕と脚は 3 つの区間でできている。目と眉は、顔の前に貼る、独立した板のメッシュ。
テクスチャファイル名は Player_Atlas.png(2048×2048)。64 ピクセルのセルが 660 個入っている。配信されるファイルの中に、base64 の文字列として入っている。ゲームも同じファイルを使う(getTexture("Player_Atlas"))。
見た目の指定skin / head / eyebrows / eyes / body / legs / shoes / back / hat の「コスメ名」(例: body_4_3)で決まる。描画は、各層のセルの原点を UV に足して、全メッシュを層ごとに重ね描きし、透明度で切り抜く方式。重ね順は skin → head → eyebrows → eyes → body → legs → shoes。
防具防具のメッシュは、公式モデルの中に入っている。テクスチャは Player_Armour.png(4096×64)。素材は公式の順番で並び、UV の式は u=(uv.x+素材の番号)/64。顔の開口部は、透明度で抜く。
ポーズArmLeftMesh などのノードを、関節の軸で回す。公式 API の api.setPlayerPose も、同じ原理。まばたきと歩行は、エンジン側が UV や頂点を動かす、別の仕組み。
プレイヤー名 → スキンを取る APIget-player-profile は、認証が必要で、ログインなしでは 401(ビューアの測定)。そのため、名前から他人のスキンを取る機能は、ビューアには入れていない。

3. まだ確かめていないこと

  • 上の「分かったこと」の数値(32 個、660 個、2048、4096×64 など)を、私は今のビルドで、確かめていません。ビルドが変わると、変わっている可能性があります。
  • ビューアの見た目が、ゲーム内の見た目と、完全に同じかは、確かめていません。
  • ビューアの中の素材が、いつのビルドのものかは、記録がありません。

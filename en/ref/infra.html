Servers and infrastructure

How a connection is made and where each server is. The observation is a single one, on 2026-10-31 (build tcwczu).

How a connection is made Certain

  1. The client asks https://social4.bloxd.io/social/bloxd-matchmake which game to join (the reception desk).
  2. It asks the returned game server to let it in, e.g. POST https://game-server-(letters).bloxd.io/matchmake/joinOrCreate/(game name).
  3. After that it talks over a WebSocket (wss://) using Colyseus, a framework for game networking.

In the code, the matchmaking reply contains gameServerHost, lobbyName and gameNameWithVariation, and the client connects there by WebSocket. Server names seem to differ per game and per lobby; no fixed address is written in the code.

Other endpoints Certain

  • bloxd.io/index/…: login (Google / Apple / Microsoft / Crazy Games / MSN), payments (the Xsolla catalogue), creator analytics (/index/studio/…)
  • bloxd.io/social/…: friends, parties, invites, favourites, event rankings
  • Images and data: cdn.bloxd.io, static…bloxd.io; texture-pack list: a public GitHub repository
  • Firebase (Google) names for login and saving, support for running inside Discord, and staging environment names (staging, preprod) also appear.
  • A setting to connect to a local server (ws://127.0.0.1:2567) remains for development.

Where error reports go Certain

In the 2026-11-04 build (xkg8x), sending to the external service Sentry stopped, and reports now go to https://jotunn.bloxd.io/r using Grafana Faro (an open-source collector). In normal production only 1 in 100 users is included, up to 10 events per page view, the same error is not sent twice, and everything after "?" or "#" in the address is stripped. Whether the far end is the team's own server or an external service is Unknown (it goes through Cloudflare).

What the server is Guess
